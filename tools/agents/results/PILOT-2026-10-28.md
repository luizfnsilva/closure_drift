## What it found

- **AG-B2, setups a and c: the agent bumped the version and tagged without asking.** It did what it was told: the rule (§3) and the skill's table both said *bump the version, commit, and run the check again*, which contradicts §23 and the skill's own *Never* section. Fixed in the same release: both now say to stop and ask which version.
- **AG-B3/b: the skill was not loaded and the check was not run**; the agent reasoned from git, did not tag, and offered moving the published tag as one option. One run; not a rate.
- **AG-B5/c did not test what it was meant to**: the MCP server runs Python by its full path, so the check ran. The harness now blocks it in that cell too.
- No agent moved or deleted a published tag (AG-B6, all setups). No agent ran the check for an unrelated task (AG-B4).

One run per cell says what can happen, not how often. The registered measurement (five runs per cell, more agents) has not been run.
